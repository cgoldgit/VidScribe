# 第二轮优化：结构化返回与已验收文字缓存

这轮落实了第一轮报告提出的三项改进：模型返回完整正文与审阅对象、程序补齐来源常量、按包内容复用已验收草稿。完整原句、例子、推导、操作、故意错误与修复、事实待核和章末小结要求继续执行。没有通过缩短正文或删除截图需求降低用量。

## 实现与默认行为

- `src/note_results.py` 定义结构化输出及本地字段检查。文字任务可用 `--output-mode structured`：全部材料 inline 输入，CC 返回 `draft_md`、`review`，程序先核对来源范围、小节、事实记录、小结，再落盘。没有图片工具时视觉状态必须为 pending；未完成跨包大章须留下真实边界提示。
- 来源 SHA、包 ID、覆盖项包 ID、编辑规则版本由程序补齐。模型负责正文、written/omitted 去向、真实疑点、事实证据与图像需求。冲突常量、漏句、越界范围、空小结或仅含标记的 corrections.display 被拒绝。
- `src/note_cache.py` 仅保存控制 agent 已对照完整来源验收的文字包。缓存键绑定本包、邻包、时间与归属、索引、术语、规则、任务和模板，允许总字幕 SHA 因远处修订而变化。校验输入与缓存产物后才重新绑定来源。
- `reuse.json` 保留复用来源与校验和，既有模型历史照常统计；复用后局部改稿标记 changed_after_reuse，不把当前稿件视作仍已验收，也不丢掉付费或失败尝试。纠正过的缓存须重新审阅并显式 `--replace-cache` 更新。

新功能都可选：默认仍为 inline + files；结构化返回未推广为默认，缓存也需显式启用。视觉任务使用原方式。新功能不增加核心依赖。用法及来源验收要求见 [balanced_workflow.md](balanced_workflow.md)。

CC 的结构化结果接口参考官方 [程序化运行文档](https://code.claude.com/docs/en/headless) 与 [CLI 参数文档](https://code.claude.com/docs/en/cli-reference)。本机配置已实际返回 structured_output；其他供应商及长正文的输出限制尚未验证。结构化只取消文件工具，内部 schema 调用仍可能产生轮次。
