## 三个选项

| 选项 | 改动 | 预期收益与局限 |
|---|---|---|
| A：保守优化 | 完整原句采用单行 ID/起始时间；结束时间和完整元数据留给程序；候选改短表；支持范围审阅；程序合稿、编号，模型只修边界和异常 | 减少重复材料与机械输出，改动较小。主会话仍可能累积大量图片，难以充分控制长会话消耗 |
| B：平衡降耗，推荐 | 包含 A；章节写作分开上下文；视觉核查按小批次独立运行，保存图片 SHA、用途、可见内容和不确定项；主 agent 只接收摘要、文件路径和异常；局部修订并限制重试 | 直接处理这次主要的历史上下文累积。需改造任务交接，确保跨包例子、术语和视觉结果没有丢失 |
| C：低成本初稿 | 包含精简输入与独立处理；文字轻度整理，规则辅助选图，只对明显指图或疑难帧调用视觉模型；常规全图复核交给人工 | 视觉调用更少；无关图、细微页面变化遗漏、图文对应不准确的风险增加，不能作为同等质量的成品模式 |

三个方案都不通过删掉例子、推导和操作过程来省 token。B 的图片批次可先以 3–6 张相关候选为试验起点；这限制单次上下文，不限制全片必要图片数量。出现不确定内容时记录异常，不能因达到预算而宣布质量检查通过。

更大的后续方案是独立 Python 调用编排：CC 启动任务，程序控制每次模型输入、状态、预算与重试。它更方便控制成本，但增加模型接口和运行器的维护工作，暂不作为本轮前置要求。

## 建议实施与验收

1. 选择方案后实现精简输入与范围审阅，保持旧 schema 可读。测试范围重叠、缺口、越界、跨包和单句，不只比较文件大小。
2. B 增加章节/视觉交接记录：来源 SHA、稳定小节 ID、图片 SHA、已确认事实、歧义、边界续接和任务状态。主会话不回收全部图片和全文。
3. 记录每个阶段的实际 usage：未缓存输入、缓存输入、输出、响应数、图片读取数、重试与费用。保留 API 原始 usage 字段，避免重复累计缓存或流式块。
4. 同一视频的实验稿放入独立目录，不覆盖本次成品。比较主要例子、操作过程、配图需求、未解决歧义、人工修订时间及实际账单。
5. 降耗幅度以同视频实际重跑为准，不承诺固定百分比。API 硬缓存与按来源/提示词/模型版本保存的产物复用分别管理；图片或来源变化时确认记录失效。
