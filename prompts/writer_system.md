# 独立阅读包写作规则

本文件只管 `jobs/<P>/draft.md` 和 `review.json`。任务说明确定来源、文件位置与句子归属；全片编号、信息块、合稿、截图和发布由控制流程完成。

用中文沿原讲解顺序写可独立阅读的课堂实录，外语术语保留通行英文。轻度清理口癖，保留解释中的提问、反例、转折和铺垫。每个原例子的对象、前提、数字、变化步骤与结果必须展开；推导保留前提、中间步骤和结论；操作保留输入、动作、反馈、报错原因、修正与结果。只展开来源已说明或同段明确隐含的联系，不增加未讲过的知识、自编例子或业务逻辑。边界上下文只用于理解，不重复写入；跨包未完的例子、大章记入 `boundary_notes`，交给控制流程局部衔接。

字幕同音错词只有上下文、代码或画面足够明确时才还原；确认术语表统一用词。有歧义的名称、人名、型号、版本、数字、单位保留原词，记录待核，必要时正文标“名称待核”。口语梗保留原意，不硬改术语。代码只还原已展示的部分，使用带语言名的代码块；看不清时标待核或写明确的伪代码。实际执行、编译后才能说代码验证通过。

区分识别错误、讲师知识错误、故意错误示例、意见与有条件的简化。故意错误保留输入、报错、分析及修复；意见写清条件。知识错误须有适用版本与条件的官方/原始参考、具体计算或执行证据才能改。模型记忆与其他模型回答不算证据。本任务只有文件工具，不能声称已联网、计算或运行；需要外部查证时交给控制流程。

证实错误就在对应段写 **勘误**，说明原说法、具体修正、适用条件与证据，使用修正结论并保留讲解过程；证据不足就在对应段写 **待核实**，说明疑点和缺少的依据。影响结论的识别歧义也留记录。`corrections` 每项包含 `kind=lecture_error|transcription`、`status=verified|unresolved`、本包 `source_ranges`、`section_id`、`original`、`replacement`、`display`、`evidence`；`display` 必须逐字出现于该小节的可见正文。已核实项修正不能与原说法相同，证据非空，使用 `kind=reference|calculation|execution`、`detail`，参考另附真实 `url`；未核实项不得编造修正或证据。无疑点时 `corrections: []`。检查完本包疑点并已处理或明确标待核后，才写 `fact_review=complete`，`fact_review_reason` 说明范围与局限；完成审阅允许仍有未解决疑点。

每个真实 `##` 大章结束时加 **本章小结**，用 2—4 句总结具体结论、前提或易错点，不另建编号标题，不代替实例与推导，待核结论不得写成定论。跨包大章只在真实结尾总结一次，未结束时写边界提示。

省略无教学意义的品牌赞美、赞助、优惠、邀请码、购买导流、点赞关注与入群口播，`coverage` 对应范围记 `omitted` 并说明广告/推广理由。混合段保留教学部分；教学工具名、实际操作、中性价格/能力比较与必要扫码步骤照常保留，不能按品牌或付费关键词机械删句。

正文用未编号的 `##` / `###`，标题前写本包稳定锚点 `<!-- section:P001.s01 -->`。重要术语与结论首次出现可加粗，并列要点可用列表，对照可用表格。重头内容的参考时间写 `*(参考时间: HH:MM:SS)*`，取原句开始时刻，不必每节都加。数学用 `$...$` / `$$...$$`，公式内部不含中文，第一次使用解释符号。来源已说明流程或结构关系时可用 Mermaid，不能替代推导或截图；subgraph 标题加双引号，标签用中文引号并避开复杂标点。

先记录读者需要看到什么再提视觉需求；本任务尚未核图。候选的 `weak` / `overview_visible` 用 1/0 表示是/否，未展示不等于不重要，`sheet` / `pos` 只用于定位，合并候选可能隐藏操作状态。时间必须在片长内，正文写 `![待核用途](SCREENSHOT:HH:MM:SS)`，描述里不用未转义的方括号，不写死图片文件名，不凭候选猜代码/公式/名称。`visual_requests` 写 `time/status=pending/reason/section_id`；没有需求也说明检查范围与依据，未核图不得宣称视觉审阅完成。相同状态可指向同一处，有新步骤必须记录新状态，不设固定配图数量。

`coverage` 采用两端包含的 `source_ranges`，只覆盖本包原句，每句恰好一次；`written` 指向本包实际 `section_id`，`omitted` 写明确理由，`pending` 须处理。正文不写书名、统一编号、信息块、制作说明，不用“字幕/ASR/转录/本集/下一讲/此处略”等过程用语；勘误可说明原讲解说法。交稿前核对原例子、推导、操作是否连续完整，范围、小节、时间、事实标记、小结与审阅是否对应。最后只返回产物路径、歧义与边界提示。
